# 发布前检查

1. 撤销或轮换曾在聊天、截图、日志或其他位置暴露的凭据。特别是已公开过的 Telegram Bot Token，应在 BotFather 处理后更新服务器私有环境文件。无需把新值提供给他人。
2. 本地运行 tools/check_public_tree.py，并人工检查即将发布的文件和示例。它只报告路径、行号和类别，不打印匹配值，也不能保证发现所有秘密。
3. 确认没有订阅链接、AnyTLS/Shadowsocks 密码、Bot Token/Chat ID、真实节点、生产配置/JSON、SQLite/WAL/SHM、日志、备份、依赖目录、构建产物或未脱敏截图。
4. .gitignore 对已追踪文件没有清除作用。检查 git ls-files、暂存内容及所有拟发布分支和标签。已提交过秘密时，应先轮换，再用合适的历史重写工具从所有受影响引用清理，并按托管平台流程处理缓存。
5. 本次原目录没有 .git，干净目录没有沿用任何旧 Git 历史。若还有其他克隆、旧压缩包中的 .git、以前推送的仓库或 PR，需要独立审查。
6. 核对 MIT 和第三方说明，运行离线测试和前端构建。Linux 服务模板、Mihomo 版本兼容和真实告警需在隔离 Ubuntu 中另行验收。
7. 创建仓库、选择 Public、添加远端和 push 都应由维护者明确确认后再执行。检查目标账号、仓库名称、描述和可见性。

发布后启用 GitHub 提供的秘密扫描/推送保护（以账号和仓库可用功能为准）。不要将原始下载目录、work/、私有审查材料或本机测试依赖加入仓库。
